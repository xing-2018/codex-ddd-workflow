# 使用指南

## 项目开发

描述目标、现有行为和约束，由ddd-flow选择需求、设计、实施或修复方法。需求与新行为先明确，获得执行授权后完成实现及获准检查。

```text
使用ddd-flow设计并实现筛选功能。先说明受影响行为和最小设计，等我批准后再修改。
```

已有批准设计时，提供其位置和允许实施的范围。只读诊断、独立审阅和提出建议均不自动授权修改。

## 诊断与审阅

```text
使用ddd-flow只读诊断页面首次打开失败的原因，先自行复现可观察症状，返回证据与最小修复方向。
```

```text
使用ddd-review审阅当前差异，分别判断设计一致性和工程质量，先不修改代码。
```

## 文档与指令

中文文档使用chinese-docs，交付格式由用户明确指定。代理指令使用writing-for-agents。TDD按其触发条件使用，是否运行测试仍服从目标项目与用户授权。

## 按项目能力

先核对任务是否需要、版本是否适用和工具是否可用，再选择非常驻Skill。安装不授权操作真实软件、模型、设备、账户或发布内容；具体动作由当前任务另行授权。
