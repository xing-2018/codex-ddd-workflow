# Review：方案与代码审阅

> 仅供人工阅读的中文译本，对应同目录[SKILL.md](SKILL.md)。本文件不是Skill加载入口；执行规则以原文为准。方案审阅参考另有中文审阅副本，其他引用保留原文。

用途：针对实施前冻结设计草案、代码差异或明确代码路径快照，审查需求一致性和工程质量。

对冻结范围分别进行**Design（需求或规范一致性）**与**Standards（工程质量）**审阅。一个轴通过不能抵消另一个轴失败。默认只读；修复需要明确请求，或外围设计／实施任务中覆盖被审阅对象的授权。

## 选择审阅模式

- **design-proposal**：实施前的设计草案或重新考虑的设计决定。只读[方案方法](references/design-proposal.md)及当前必要的架构资料，不要求实现或代码测试已存在。
- **code**：实现差异或明确代码路径快照，包括实施后和独立代码审阅。只读[代码方法](references/code-review.md)及当前必要的代码／测试规范。方案PASS不能替代实现审阅。

按请求对象选择模式，不按是否有代码选择；只解决会影响判断的歧义，不预加载两种方法。审阅不授权改写需求、设计、批准记录或实现。两种参考的中文副本仅供人工审阅。

## 公共审阅契约

复用已有适用AGENTS、领域上下文、批准需求／设计，只补缺失或失效的权威，包括相关专项及上游依据。没有设计文件时，当前用户要求、可恢复会话批准和已建立的Authority Baseline仍有效。任务、配置、代码和通过的测试是证据，不是批准。缺少实质权威时Design为NOT_ASSESSABLE，已批准条款冲突时为BLOCKED，两种情况均继续Standards。不能改设计或降低验收来使偏离合理化。

涉及产品变化、版本或交付时，适用[版本与交付](../ddd-flow/references/versioning-and-delivery.md)，只读取尚未解决的指导，复用有效项目配置和判断。明确可丢弃且不改变产品或交付物的夹具没有版本与交付工作。针对冻结范围评估兼容性、已确认基线、适用版本与交付物配置及证据。仅源码交付的部分检查可以保留为待完成；独立审阅既不升版，也不构建。相关发现仍归入既有两个轴。

复用主会话有效执行职责判断和证据。小型审阅本地完成；实质性直接审阅缺少判断时，只提取[Choose execution ownership](../ddd-flow/SKILL.md#choose-execution-ownership)，不遍历flow。有依据且获准的委派提供公共契约／报告片段、选中模式方法、有界Worker contract及有效来源身份。worker只补缺失片段，保持只读，不再委派或重复管理判断，返回两轴由主会话核验和协调获准修复；不读另一模式或派发／状态／验收／恢复章节。一个worker可评两轴。

只有复用／失效未决时才取得[Evidence validity](../ddd-flow/references/execution.md#evidence-validity)，有效片段直接复用。模式方法持有各自冻结对象和特定声明检查；审阅、提交或交接本身不触发复跑。

## 4. 分别报告两个轴

主会话面向用户的报告先说明总体处理建议和主要影响，再分别给出结论及依据。Design、Standards发现与需求追溯仍须可区分，不能相互抵消或掩盖：

- Design：`PASS`、`FAIL`、`BLOCKED`或`NOT_ASSESSABLE`。
- Standards：`PASS`、`FAIL`或`BLOCKED`。

每项结论绑定冻结对象、覆盖路径及已评估声明。局部变更通过不认证整个实现。已观察的范围外问题与未评估声明放入现有报告，不自动扩大审查或修复范围。

每项发现引用证据，说明实际影响和最小修正方向。不合并评分，不掩盖无法评估的Design轴。小型或无问题审阅无需空发现或无关附录。委派审阅保留提供的Worker contract摘录中的结果与身份字段，并包含两个结论；主会话验收当前证据并组织为便于阅读的报告。
