# Chinese Docs：中文文档

> 仅供人工阅读的中文译本，对应同目录[SKILL.md](SKILL.md)。本文件不是Skill加载入口；执行规则以原文为准。仅翻译入口正文及用途说明，引用文件保留原文。

用途：创建、修订、审阅和交付较完整的中文文档、仓库README或独立Mermaid图。

负责较完整文档的结构、证据、中文表达和交付，并提供独立图表路径。普通回答、微小编辑和简单摘要无需使用本Skill。软件需求与设计决策仍由`ddd-flow`负责；改善表达时，不改变行为、领域或数据语义、范围及批准状态。

文档默认以Markdown在会话中交付；只有获准落盘时才保存文件。DOCX、PDF或多格式输出须有明确格式要求，正式报告或模板本身不构成该要求。软件、原型和必要资产保留其已批准交付契约。明确要求仅调整格式时，保留内容，只读取所选格式约定。

## 选择路径

只画、修订或排查一张独立Mermaid图时，读取[Mermaid方法](references/mermaid.md)及确实适用的语法或导出参考，并按该方法完成请求；下方文档指导不适用。DDD设计可以直接读取图表方法，无须启动文档任务。

文档任务则确定操作类型（`create`、`revise`、`review`、`format-only`）、文档类型、证据依据和所需格式。类型或模板不明确时，使用[路由说明](references/routing.md)。只读取适用的分支：

| 条件 | 必读参考 |
| --- | --- |
| 中文起草或修订 | [中文写作](references/chinese-writing.md) |
| 明确要求母语化或“去AI味”，或全文存在系统性的翻译腔、程式化表达 | [自然中文](references/natural-chinese.md) |
| 内容需要来源支撑，或涉及仓库、外部事实 | [证据](references/evidence.md) |
| 仓库README，开始检查仓库之前 | [README](references/readme.md) |
| Markdown内容或交付 | [Markdown](references/markdown.md) |
| 明确要求DOCX，包括仅调整格式 | [交付与模板选择](references/routing.md#交付路由) |
| 明确要求PDF，包括仅调整格式 | [交付与模板选择](references/routing.md#交付路由) |
| 较完整或正式文档的内容审阅与读者检查 | [审阅](references/review.md) |

采用一次“证据—起草或修订—审阅—所选格式交付”流程，不加载、生成或检查未要求格式。保留README原有语言约定；母语化修订须保留事实、文体、术语和确实存在的并列结构。

## 按工作规模推进

- 小范围修订：阅读目标及证据，做精确修改，完成简要审阅。
- 常规文档：确认上下文和证据，起草或修订，审阅并交付。
- 较完整或正式文档：明确简短的文档约定，包括目的、读者、范围、来源、结构、格式和验收要求，再起草、审阅并进行读者检查。用户或项目已确定的选择无需重复批准。
- 仅调整格式：保留内容，执行适用的结构与视觉质量检查。

有帮助时采用最接近的现有模板，不凭空增设章节或无依据的事实。保留优质内容，以及用户提供的术语、组织方式和有依据的细节。区分事实、推断、假设和未知；在授权范围内，通过第一手来源核验可能变化的外部信息。不得编造数据、引用、作者或审阅者信息、完成状态。仅将确实未解决的事实标为`[待补充]`。

较完整的报告先写正文，再写摘要。依据写作参考处理术语、行文和母语化表达；未经相应要求，不模仿特定作者或引入口语风格。对内容源整体审阅一次，检查目的、范围、结构、证据、矛盾、冗余、术语、机械表达和Markdown可移植性。格式转换后，只有发现内容缺陷时才重复内容审阅。

## 交付与完成

生成或渲染前区分交付物、必要资产和临时构建文件、检查图、日志。使用项目指定位置；缺省使用获准项目目录内本任务独立位置，包括Git忽略目录。外部位置需要明确授权。检查工具默认输出与伴随文件并定向到该位置；只能在输出旁生成伴随文件时，先在工作目录构建，再复制验收后的交付物与必要资产。完成必需检查和证据记录前保留验证产物。

Markdown检查可移植性和本地链接，不生成DOCX/PDF或进行其渲染检查。明确要求DOCX时完成相应模板、结构和视觉检查；内置报告从DOTX继承基础格式，只应用word.md定义的个人覆盖。纯格式处理另需内容保护证据，结构通过不证明视觉版式或页码正确。PDF完成所选参考要求的渲染检查。共享内容只审阅一次，复用有效证据；转换成功不足以证明交付合格。明确要求多格式时，分别报告其限制。

完成前直接检查源文件目录和交付目录中本任务产生的文件，包括被Git忽略的文件。Git状态干净或存在忽略规则不能证明落盘位置正确。在授权范围内修正本任务产物的位置；保留既有证据并报告尚未解决的清理问题。正文引用的图片属于交付资产，不能当作临时检查图处理。

所需文档必须与证据一致、脱离聊天上下文仍可理解、连贯且前后一致，每种交付格式均完成必需检查，才算完成。报告内容源、派生文件、查阅的证据、实际验证和未解决的假设。仅审阅任务返回发现与修正方向，不进行未经授权的编辑。
