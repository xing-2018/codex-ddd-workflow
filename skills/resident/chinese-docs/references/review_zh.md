# 内容审阅与无上下文读者检查｜中文审阅副本

英文执行参考为[review.md](review.md)。本文件用于人工审阅，不作为额外执行指导加载。

较完整或正式文档在交付前进行一次内容审阅。多格式交付共享这次审阅，各格式只追加自己的版式或结构检查。

## 整体内容审阅

从相关对话及项目负责文件恢复完整适用文档约定：目的、读者、覆盖范围、结构、前文纠正、禁止内容和必须保留的事实。新反馈只改变涉及条款。复用已确定决定和指导，不新增台账，不重复询问已确定选择。

将实际段落和场景与约定核对后，才能判定内容已就绪。检查：

- 标题、概述、正文和结论回答同一个问题；目的、读者、范围和排除项一致。
- 要求的覆盖内容齐全；明确要求完整的结果没有变成未说明的抽样，获准子集符合已说明边界。
- 前文纠正在新增或重写内容中仍然成立；禁止内容没有换一种措辞重新出现。
- 章节顺序符合读者理解和行动，而非聊天生成顺序。
- 关键判断有证据，推断、假设和未知明确区分；术语、缩写、单位、符号、状态名和接口一致。
- 没有矛盾、重复段落、空泛套话、无依据扩写或与目的无关内容。
- 具体操作符合适用产品行为和批准设计；输入、选择和指代延续到后续步骤，连续对话有相互依赖的追问，而非无关单轮问题拼接。实现缺失不删除批准设计目标，预期回答不证明能力已实现。
- 同级章节没有机械重复定义、列表、拔高，也不依赖固定路标和预告式结论。
- 图表、公式、代码和引用在正文中有明确作用；Markdown符合[可移植规则](markdown.md)。

软件设计文档沿用已适用的[开发正文边界](../../ddd-design/references/design-documents.md#developer-facing-content)，只在缺失或失效时补读。写作和维护叙述归既有任务或证据负责文件，保留实现需要的来源、适用条件和未决事实。按每段用途判断，不用“来源”“文件”等关键词黑名单。

在既有写入授权内修正内容偏差后交付；只读审阅则报告偏差。未决语义选择返回其负责人，再完成适用静态和格式检查。链接、格式、数量和哈希只证明各自属性，不能代替内容比对或认证内容符合要求。

技术报告写清具体约束和局限，不用笼统风险措辞替代。

用户要求母语化，或审阅发现系统性机械表达时，读取[自然中文](natural-chinese.md)，按文档、段落、句子和表面层复查。保留事实、术语、步骤和文体；没有系统性问题时不重写文风。

## 无上下文读者检查

重要文档需刻意从“只有文件、看不到聊天和隐藏上下文”的读者角度阅读。独立审阅者可能有帮助，但不是必需。

至少回答：

1. 文档支持什么决定、理解或行动？
2. 核心结论或方案是什么？
3. 依赖哪些前提、约束和假设？
4. 关键判断的证据在哪里？
5. 读者下一步应做什么，若文档类型需要行动？
6. 哪些术语或缺失步骤会使新成员或外部读者困惑？
7. 连续三个同级章节是否呈机械结构，还是各自结构服务于不同功能？

将答案判为`direct`、`indirect`或`missing`。补齐范围内的`missing`；`indirect`使读者必须猜测关键联系时，改成直接表达。

## 停止条件

完整目的和范围得到覆盖，关键判断可追溯，前文纠正保持，没有重要矛盾、重复或系统性机械表达，术语一致，无上下文读者能理解主要结论时停止。不为完整感添加无用章节，不为自然感添加装饰性表达。
