# Markdown 交付规则

Markdown 是内容变化任务的默认内容权威，应保持 UTF-8、Typora 友好，并能稳定转换到 DOCX/PDF。

## 结构与语法

- 每个独立文档最多一个一级标题 `#`；章节按层级连续展开，不跳级，通常不超过三级。
- 段落和块级元素之间用空行，不用 Tab、连续空格、空段落、`<br>` 或行尾双空格模拟版式。
- 列表最多两层；更深结构改用小节。正文优先连续段落，不把报告写成清单堆叠。
- 命令、配置、JSON、SQL、日志使用带语言标识的 fenced code block；不要为了换行改变可执行语义。
- 项目文件、字段、命令和状态值使用代码格式；项目内链接优先相对路径。

除非用户模板或转换链路明确要求，不默认使用脚注、任务列表、GitHub 提示块、`<details>`、原始 HTML、内嵌 CSS 或自定义分页标签。正式 PDF 所需的封面、目录、页眉页脚和分页由 PDF 交付阶段负责。

## 表格

表格适合短文本和结构化比较。默认控制在四列以内；五列以上、单元格含长段落或比较维度过多时，优先拆表或改成分项小节。单元格不放嵌套列表或长段文字；竖线写成 `\|`。

正式报告的表题/图题规则由目标 DOCX/PDF 合同决定；仅 Markdown 交付时应使用清晰的普通文本题注。

## 图片与图表

图片使用标准 Markdown 语法和相对路径，例如：

```markdown
![系统架构图](assets/system-architecture.png)
```

正文引用截图作为说明或证据时，每张截图都须在交付的 Markdown 中用上述图片语法内嵌，让读者打开文档即可看到画面。可按相关章节集中展示截图，并另附原图链接或文件清单；单独使用普通超链接只提供跳转，不能替代内嵌展示。截图无法内嵌时说明缺口，不宣称截图已在文档中可见。

交付前确认本地目标存在。不要引用临时目录、本机绝对路径、需要登录的附件地址或短期签名 URL。

标准 Markdown 图片语法没有通用的显示宽度参数。以目标阅读器预览交付文件；未指定阅读器时按 Typora 检查。最终保留的插图在正文或表格中应不超出所在栏宽，保持宽高比、不裁剪，图中文字在实际显示尺寸下可辨认。若需控制宽度，优先制作适合显示的派生图片；采用阅读器专属尺寸语法或样式时，须说明依赖并在目标阅读器核对。图片路径有效或原始像素足够，不等于显示尺寸合格。

Mermaid 可以作为 Markdown 源中的受控扩展，但实际生成正式 PDF/DOCX 时必须确认转换链支持；不支持时先渲染为 SVG/PNG。页面型流程图优先采用纵向布局，避免因横向过宽导致文字不可读。

## 公式

数学公式统一使用 LaTeX 且以美元符号分隔：行内 `$...$`，独立公式：

```markdown
$$
E = mc^2
$$
```

不要混用 `\(...\)`、`\[...\]` 或 `equation` 环境作为 Markdown 公式边界。普通美元符号需要转义。

从 DOCX 等源文档转换时，先区分正文插图和作为图片、嵌入对象保存的公式。公式须转写为上述 LaTeX 形式，并对照原式核对符号、上下标、分式、矩阵和编号；不能以公式图片替代可编辑的 Markdown 公式。无法可靠还原的公式应保留原图作核对依据，列出具体位置与未完成项，不宣称该公式已转换或全文转换完成。

## 交付前检查

确认标题层级、列表深度、代码语言标识、表格宽度、图片路径、公式边界和链接均可解析；没有为排版而插入的不可见/硬换行技巧。在目标阅读器打开交付的 Markdown，确认正文引用的每张截图实际显示、关键文字可辨；只有图片链接、损坏占位或文件存在均不算通过。源文档转换还须核对公式对象、公式图片和正文插图的去向，在目标阅读器检查公式呈现及最终保留插图的显示尺寸与可读性；解析成功或图片文件存在不能代替这些检查。无法完成预览时，说明未验证的排版项，不宣称符合目标阅读器的排版要求。若只交付 Markdown，明确尚未实际验证 DOCX/PDF 版式；若同时交付其他格式，继续执行对应格式合同。
