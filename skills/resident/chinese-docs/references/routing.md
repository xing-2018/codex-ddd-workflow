# 文档路由

先判断读者任务，再判断交付格式；不要把模板名称当成路由依据。

## 文档类型

| 用户意图 | 推荐模板/路由 | 核心目标 |
| --- | --- | --- |
| 明确产品要做什么、为谁做、成功标准是什么 | `../assets/templates/product-requirements.md` | 用户、场景、范围、成功标准 |
| 说明已确定需求如何实现、有哪些取舍、如何验证 | `../assets/templates/technical-design-spec.md` | 架构、接口、数据、失败语义、验证 |
| 比较方案、调研技术、综合资料并形成建议 | `../assets/templates/research-analysis-report.md` | 问题、证据、比较、结论与建议 |
| 记录重要选择及后果 | `../assets/templates/decision-record.md` | 背景、决定、理由、后果、复审条件 |
| 汇报阶段成果、风险和下一步 | `../assets/templates/progress-review-report.md` | 基线、完成情况、证据、阻塞、计划 |
| 指导完成操作、交接或应急处理 | `../assets/templates/guide-runbook.md` | 前置条件、步骤、验证、异常、恢复 |
| 让仓库读者尽快理解项目并完成首次成功 | README 路由 | 定位、能力、最短上手路径、必要配置 |

当软件需求或技术设计本身仍未决定时，由 `ddd-flow` 负责决定；本 Skill 只把已经确定或用户明确提供的内容形成高质量文档。

## 操作路由

- `create`：从已提供/已核实材料建立新的文档事实表达。
- `revise`：保留强内容，只修改用户指定范围及其必要上下文。
- `review`：只读检查事实、结构、表达、证据和可读性；未经授权不改文件。
- `format-only`：内容不变，只完成 Markdown/DOCX/PDF 的格式与版式处理。

“去AI味”、母语化改写和自然度润色按授权落入`revise`或`review`，不是独立文档类型。显式要求此类处理，或长文出现系统性翻译腔、模板结构、空泛判断时，读取`chinese-writing.md`和`natural-chinese.md`；普通格式整理不触发内容改写。

## 交付路由

默认仅交付Markdown；未要求保存文件时在对话中交付。仅当用户明确要求DOCX、PDF或多格式时，才进入对应分支。正式文体、文档类型、已有模板或生成器不构成格式请求。只读取、生成和验证当前所需格式，不自动制作另一种格式或提出格式确认问题。格式转换不授权增加正文范围或持久化目标。

- 仅 Markdown：以 Markdown 为最终交付，读取 `markdown.md`。
- 通用DOCX：内容变化时先稳定Markdown，再按可用文档生成能力的通用Word合同生成，执行适用的结构验证并全页检查；保留读者任务所需的准确命令、配置、仓库相对路径及安装路径。不得仅因输出为Word而读取或应用`word.md`。
- bundled正式研究报告DOCX：用户／项目明确采用，或类型已确定为正式研究报告且无更强模板合同时，读取[`word.md`](word.md)。DOTX唯一提供基础版式，word.md说明继承与个人覆盖；生成和审计直接读模板。既有内容与覆盖冲突时先报告，不因模板采用获得删减权限。完成结构审计、目录刷新和全页视觉检查；纯格式处理另核对内容，结构通过不等于整体验收。
- 用户模板DOCX：先检查用户模板的样式、结构和内容合同，再按该合同生成并完成适用的结构与视觉检查；用户未明确要求时，不得套用bundled研究报告的样式ID或内容边界。
- 通用PDF：指南、README和操作说明等沿用文档结构，按阅读需要排版，读取[PDF交付](pdf.md)的共同要求；不自动采用报告封面、目录、章节编号或章间分页。
- 正式中文科技/技术报告PDF：没有更强模板合同时，读取[PDF交付](pdf.md)中的正式报告专属流程，使用现有报告模板和生成器。
- 用户或项目模板PDF：先核对模板的页面、字体、编号、图表和分页合同，再按[PDF交付](pdf.md)的共同要求完成转换与检查；报告默认样式不得覆盖该合同。
- 多格式：只审一次内容；Markdown 为内容权威，DOCX/PDF 分别执行适用的格式级验收。

DOCX及PDF模板选择依次遵循用户明确要求、项目已有合同和对应文档类型的默认方式。能从已有内容确定类型时直接选择；仅在选择实质影响交付且无法确定时询问。内容变化先稳定Markdown；仅格式处理保持内容，不新增摘要、结论等章节。

不要因为存在模板而强制生成无用章节，也不要为了“完整”增加缺乏证据的内容。
