# 中文写作风格

本 skill 默认服务中文 Markdown 文档。除非用户明确要求纯英文，正文应使用简体中文；代码、命令、路径、字段名、状态值、错误信息和产品专有名词保持原文。

## 写作目标

写正式、自然、可审核的中文。先完成读者任务，再追求文风：说明对象是什么、依据在哪里、判断到什么边界、读者需要采取什么行动。自然不等于口语化，也不等于模仿名家；技术准确性、证据和可执行性始终优先。

每个抽象判断尽量落到具体对象、动作、约束、成本或结果。没有机制或证据时，不用“赋能”“重塑”“全面提升”“开启新篇章”等大词替代内容，也不靠“值得注意的是”“从某种意义上说”制造判断感。

## 结构与推进

文档结构服从读者的理解和行动顺序，不服从对话生成顺序。开头尽快交代问题、范围或任务；主体中的每一节应承担明确功能；结尾回应前文提出的问题、决定或下一步，不临时拔高到更大的命题。

段落优先，列表适度。连续解释、背景、分析和结论用段落；真实并列项、步骤、字段、状态和验收条件用列表或表格。不要为了“自然”取消必要的编号步骤，也不要把本可连续说明的一层意思拆成连续的“粗体标签+冒号+解释”。

避免全篇重复同一种骨架，例如每节都“定义→三点拆解→价值拔高”，或每段都以“首先/其次/最后”推进。结构确实是三项时可以写三项；没有真实分类时，不为整齐硬凑。

## 句子与段落

每段围绕一个主要意思推进，但不强求相同长度。长短句可以交替；长句包含多个条件、转折或结果时应拆开，连续短句造成口号感时应合并。

优先使用有明确主语和动作的直接表达。能调整句序解决的关系，不额外堆“基于此”“与此同时”“对于……来说”“围绕……展开”“通过……从而实现……”等连接框架。对比关系真实存在时可以使用“不是……而是……”，但不要把它当作默认强调句式。

段落之间依靠语义推进，不靠连续路标硬粘。删去路标后关系仍清楚，就直接进入事实、原因、限制或后果。

首次出现的缩写、内部代号、模块名和业务术语应解释。后文保持同一名称，不在同一文档中混用同义词。

遵循用户和项目已有的标点、引号、日期及中英文排版约定；没有约定时保持全文一致，不为“去AI味”进行与内容无关的全局格式改造。

## 标题与摘要

标题应直接标识文档对象，不写口号。摘要应回答文档要解决的问题、范围、结论和读者下一步，而不是复述目录。

章节标题保持短而明确。不要用“相关说明”“其他内容”这类难以导航的标题。

摘要、章节引言和结论各自承担不同任务，避免三处用不同措辞重复同一段话。段尾不使用“未来已来”“这只是开始”等口号式收束，也不要每节都以“接下来将……”预告下一节；优先写清当前结论、未解决约束或自然过渡。

## 列表与表格

步骤使用编号列表；无顺序的并列项使用项目符号；比较、状态、需求清单和验收口径可以使用表格。

表格应保持列数少、单元格短。若单元格需要多段文字，改用小节或列表，避免后续 PDF 渲染错位。

## 风险与限制

风险描述应具体到触发条件、影响范围和缓解方式。不要只写“存在一定风险”。

待确认事项应说明需要谁确认、确认什么、为什么影响当前文档。

判断强度应与证据匹配。删除“可能在某种程度上产生一定影响”式层层缓冲，也不把有限证据写成“必然”“彻底”“唯一”。证据不足时直接说明适用范围、条件或未知项。

## 按需深度修订

用户明确要求“去AI味”、母语化改写或解释文本为何显得机械时，或者长文系统性出现翻译腔、套话、模板结构和口号式结论时，继续读取[`natural-chinese.md`](natural-chinese.md)。普通起草只需遵循本文件，不为寻找问题而加载额外规则。
