# Writing for agents：代理指令写作

> 仅供人工阅读的中文译本，对应同目录[SKILL.md](SKILL.md)。本文件不是Skill加载入口；执行规则以原文为准。仅翻译入口正文及用途说明，引用文件保留原文。

用途：编写或审阅Skill、AGENTS.md及其引用的代理指令。

先修正指令归属与行为，再缩短文字。遵守请求范围：仅审阅保持只读；查阅某文档不授予执行其中工作流的权限。

## 明确范围与权威

阅读目标、对它生效的指令链，以及直接受影响的负责方和调用方。只有为解决具体依赖或冲突才扩大阅读。区分可发现事实、用户选择和动作权限。保留用户偏好、已批准语义、明确审阅关口及有效既有授权；消除该范围内的重复审批。

涉及Skill元数据或路由时，阅读[Skill机制](references/SKILL-MECHANICS.md)。

## 先确定归属

改写前对条款分类；混合政策与过程的条款先拆开。

| 负责方 | 内容 |
| --- | --- |
| 全局AGENTS | 跨项目用户偏好、权威与权限边界、必要条件引用 |
| 项目AGENTS | 长期项目约束与明确覆盖规则；项目过程指针 |
| Skill | 可复用任务方法、领域指导、工作流检查和完成规则 |
| Reference | 按需到达的分支细节 |
| 代码或配置 | 可低成本查明的命令、路径、版本及其他当前事实 |
| 任务或项目记录 | 决策、证据、状态和临时发现 |

某工作流跨项目有用，不代表应放进全局AGENTS。用户明确要求放置位置时予以保留；否则保留规则效果，不假定当前位置不可改变。

对每项实质性条款选择**保留、合并、迁移或移除**。迁移需要已核实的负责方和可靠进入条件；将过程交给其他文件时，保留权威政策。没有合适负责方时，报告缺口，或只创建获准的最小参考。不静默删除规则、降低权威或编辑任务范围外内容。

## 让每条指令都有作用

- 每项含义只有一个负责方。合并真正重复的内容；政策与过程、触发条件与目标不自动算重复。移除不增加必要决策或行为的无关、过时、泛泛或解释性材料。保留不明显的约束与例外。
- 共享要点留在正文，分支细节经由现有引用按需展开。每个指针说明何时读取哪个精确目标，并覆盖不同入口。先加强薄弱触发条件，不直接把目标内容复制到正文。不为把文字移出视线而新建文件或Skill。
- 明确可执行要求、所需证据、可观察完成或停止条件。把模糊强调语替换为具体检查事项。保留定义范围或权限的禁止条款，将相关规则和限制组织在一起。
- 使用平实措辞，避免自造术语或理论化解释模型行为。只有实际任务或观察到的失败才促使拆分工作流或委派，不依据猜测的注意力收益。不给长度或发现数量设置配额。

## 核验与报告

重新审视沿用的固定步骤、无条件文档预读及重复测试提示。保留保护任务特定依赖或必需检查的步骤，其余执行顺序交由代理判断。不能因为模型通常会自行检查，就删除验证要求。

完成条件应覆盖请求的可用结果，以及已授权的检查和修复。指出不涉及用户决策的中途停止点，保留明确评审关口。具体说明既有授权内可安全继续的范围，不把模型信心当成权限。

对照原始契约，审阅完整受影响段落及引用。检查归属、权威、触发覆盖、目标可达性、例外和完成条件。重要变化须用代表性决策检验；措辞匹配本身不能证明行为。

报告发现时提供文件与行号证据、影响及最小连贯修正。区分冲突、错置内容、重复和可选措辞调整；建议迁移时指出目的地。没有发现也是有效审阅结论。完成已授权编辑和必需检查，或指出精确的未决条件。

声称节省消耗时，衡量可比的前后文本，区分始终加载的描述与按需加载的正文和引用。移动文本不必然减少净上下文；未经验证的行为效果须单独报告。

针对特定模型修改指令，或用户要求对照当前模型指导时，查阅[模型指导维护](references/SKILL-MECHANICS.md#model-guidance-maintenance)。
