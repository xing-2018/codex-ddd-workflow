# Product Design交接

> 仅供人工审阅，对应[英文执行版](product-design-handoff.md)，不作为额外执行指导。

仅在当前问题已选择Product Design后、依赖写入或验证前读取。本适配把它的当前流程接到[DDD预览合同](preview-contract.md)，不调用、安装、复制或覆盖提供方。

## 创建前绑定任务

恢复已批准任务、范围、当前布局／状态及准确选定视觉源，以修订或可恢复内容身份绑定。按任务使用提供方的audit、ideation或实施入口；局部修正保留已选目标，新方向先完成当前brief及用户选择，再构建。不把提供方的候选数量复制成全部DDD任务的要求。

按提供方当前说明核对实际宿主和可调用能力。Desktop与云端Work的预览／浏览器约定不同，不在此硬编码另一宿主的URL或API。遵守工具限制及项目授权，包括computer-use显式启用。捕获、QA、查看或导出能力缺失，只让对应主张未验证，不授权安装、账号／配置变化、新对话或扩大权限。明确请求的提供方不能静默替换；改变其合同的替代路径须由用户决定。

文件或进程动作前，在既有预览计划中说明允许的写入／启动／检查及解析后的路径：项目根、创作／运行根、依赖与构建输出、提供方必需QA文件、任务证据及最终入口／资源。复用既有.planning负责文件和批准，不另建审批或调研存储。获准截图等证据只放项目任务证据位置。提供方必需QA文件保留在它要求的根，记录属性和指针；不能挪走后声称完成提供方流程。

`docs/design/prototypes/src/`可以作为创作根候选，不是已认证的提供方项目根。按当前工具／提供方合同核对，实际执行获准后再证明兼容。该目录可以有创作源码index.html，但不是另一正式审阅入口。唯一最终入口仍是`docs/design/prototypes/index.html`，配套README及设计负责文件／指针。必需路径或依赖与批准边界冲突时，先解决具体冲突再写入；不另建原型或悄悄省略必需QA。

## 导出时保留设计

在提供方构建、QA和导出中保留选定来源、代表路径、相关状态、数据含义及批准布局。对实际导出产物应用[转换与保真修复](preview-contract.md#conversion-and-fidelity-repair)。业务操作用内存状态和预设结果模拟；不能因为提供方输出可运行代码就引入真实文件、持久化、服务或计算。

提供方创作、开发预览和必需QA属于中间工作。按既有合同导出独立HTML入口与打包资源，约定路径不依赖创作检出、安装依赖、构建步骤、后端、CDN或网络请求。核对实际最终路径、依赖及附带文件；开发页面运行或构建成功不能认证导出。

保留有语义的工程图表、几何、可访问性及批注目标。提供方资产规则无法保留语义可视化时，限定它的视觉职责或取得范围／方法决定；不把可操作工程视图压成装饰位图后宣称功能等价。沿选定提供方的真实规则适当使用原有资产。

## 分开交接证据

使用既有任务／设计证据负责文件，绑定审阅来源、最终产物身份及实际检查范围，区分以下结论：

| 主张 | 所需证据 |
| --- | --- |
| 视觉与交互保真 | 实际打开来源和当前实现，在相同视口／状态比较，并操作适用主路径。 |
| 提供方构建QA | 要求的根中保存必需报告，并有真实比较、阻断修复及按当前规则重新捕获／复查。 |
| 最终离线原型 | 无产品／预览服务时直接离线打开导出入口，操作范围内路径，并按预览合同检查处理器。 |
| 原生批注支持 | 在目标宿主实际选取目标、提交批注并回传，覆盖合同要求的内容／状态。 |
| 用户设计接受 | 用户真实批准明确产物及范围，与技术结论分开。 |

不能用手写PASS替代观察，也不能用一行证据认证另一行。捕获、比较或必需QA受阻时保留提供方的blocked结论；迭代上限不能覆盖阻断问题。非阻断润色沿其真实方法停止，不无决定地循环。源码维护或只读适配审阅可以按获准范围完成，同时明确提供方运行、离线或批注仍未验证。不能把未验证原型当成完成提供方交付或已接受设计。真实设计决定交回ddd-design，另行获准的实施或交付交回ddd-flow。
