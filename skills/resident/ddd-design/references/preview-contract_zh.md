# 预览合同

> 仅供人工审阅，对应[英文执行版](preview-contract.md)，不作为额外执行指导。

使用能让用户判断真实设计决定的最小预览，区分用户可操作产物与检查证据。预览模式和批准门槛归ddd-design。被路由的专业能力可以形成或验证证据，不能降低门槛或批准设计。

创建或修改预览及配套证据前，应用[设计批准](../../ddd-flow/references/design-approval.md)：提出具体预览计划，确认明确写入授权或有效有界自主范围。UI设计、格式转换或反馈本身不授权写入。含糊解释须在依赖写入前解决，可操作预览要求不能绕过批准。

## 预览模式

| 设计问题 | 最小审阅产物与验证 |
| --- | --- |
| 交互已定的局部层级、分组、密度或文案 | 目标尺寸下的渲染静态屏幕。 |
| 完整用户流程或新交互 | 核心输入、动作、反馈与结果贯通的可操作原型。 |
| 标签页、面板、选择保留或渐进展开 | 可点击或运行的预览。 |
| 核心流程的校验、加载、过期结果、成功或失败 | 可运行转换及可见反馈；独立状态图只能补充，不能替代交互。 |
| 缩放与溢出 | 在代表尺寸操作的目标平台预览。 |
| 修改已有UI | 当前证据及满足受影响流程交互层级的拟议预览，沿用既有视觉语言。 |

除非问题明确仅限已定布局或视觉，原型请求默认包含核心输入、动作、反馈和结果的可操作路径。当前截图可支持比较，不能替代流程产物；保留用户对截图的限制。

扩展候选前，先说明用户须在预览中做什么才能判断交互。位置、顺序或输入方式的重要选择需要实际操作时，先做一条代表性完整路径，放在产品上下文中展示，再取得集中反馈后增加变体。“运行案例”可能表示交互演示、真实计算或只读回放时，先澄清，再构建较高成本路径。单方面反馈不决定其他选择；形成性检查不同于最终设计批准。

## 独立HTML交付

Web及桌面产品均通过[单一项目原型](#单一项目原型目录)交付浏览器可打开的HTML设计产物。页面共享导航、主题与内存状态。已定局部视觉问题可在同一产物中使用静态屏幕，不另设格式或位置。入口可内嵌样式、脚本和代表数据，或加载打包本地资源，但须保留直接离线打开。约定路径不能依赖安装依赖、构建命令、产品源码模块、后端、远程字体、CDN或网络请求。创作工具有用时交付其独立输出；本地URL以.html结尾不证明独立。

依据实际证据保留页面信息架构、标签、控件、主题、相关资产和交互约定。复用是保留设计上下文；创作时可只读复用适合的生产展示组件、渲染器和资产以避免重建偏离，不适合时忠实重建也有效。以一致场景数据及可见状态模拟API／store／认证／原生边界，保留相关DTO身份、单位和关系。产物仅运行界面状态与展示逻辑，不导入领域算法或业务处理器。独立输出打开时不依赖生产检出、源码导入、创作工具链或服务。不要只为预览而改生产文件。明确请求真实执行时沿下方范围路由另行处理。

桌面目标的默认窗口尺寸与平台约定从设计或配置恢复。浏览器更大时显示产品窗口及周围空间，不拉伸占满视口；更小时通过有意滚动或明确标识的缩放保留目标行为，区分浏览器视口和产品窗口尺寸。权威尺寸无法恢复时，说明供审阅的合理暂定尺寸。拟议控件应能对应目标原生控件；HTML样式不证明原生焦点、键盘或组件行为。

### 仅界面交互边界

核心控件须完成界面任务：导航、选择、编辑、校验、草稿确认／取消、筛选及可见反馈只改变内存UI状态。业务结果来自与场景、单位及标签一致的内嵌示例或预设状态；任意编辑不触发真实领域计算。应用[布局与内容默认规则](ui-design.md#stable-layout-and-task-focused-content)。模拟范围、创作细节和来源默认放必需README，不为解释原型而向产品界面加横幅、卡片、页脚或审阅控件。真实感动作会误导结果或数据时，在批准反馈或审阅区域展示最小必要说明，保留产品布局。必要校验、错误和动作反馈须可操作且可见，文档不能替代。

| 产品动作 | 原型行为 |
| --- | --- |
| 打开或导入 | 模拟选择对话并加载选定内嵌示例，不启动OS文件选择器或读取用户文件。 |
| 保存或取消 | 在内存确认或放弃草稿并显示反馈，不写文件或持久化浏览器数据。 |
| 导出 | 用界面状态演示确认、进度、成功或失败，不序列化输出文件或下载。 |
| 历史 | 选择内嵌示例和当前会话快照，不使用localStorage、sessionStorage、IndexedDB、cookies或持久存储。 |
| 计算或提交 | 显示与所选示例关联的预设加载、结果和失败，不调用领域算法、产品模块、API或服务。 |

这些控件仍须可操作；禁用或用通用“尚未实现”提示替代不展示流程。交付原型没有业务文件访问、输出生成、持久化或实时服务集成，即使称为本地、可选或仅示例也不例外。用UI状态转换表达交互，不在其后实现功能。创建及检查HTML产物、加载打包样式／脚本／图片／内嵌示例仍是允许的交付工作。本边界针对运行时业务动作，不禁止读取设计证据或写入获准设计产物。

### 多页状态与创作

路由留在同一应用中，跨导航保留批准的状态生命周期：选定实体、草稿与已应用查询、取消及过期结果可用性。独占创作可分页面源码，但返回时不重置状态。[工作区协调](../../ddd-flow/references/execution.md#shared-checkout-coordination)下由一个整合者负责共享导航／主题／构建。不以嵌入旧完整HTML快照替代当前共享组件。批准覆盖实际入口及依赖资源；生产代码和旧原型与最新批准冲突时仅作观察参考。

### 原生浏览器审阅与批注

项目原型须支持Codex内置浏览器审阅，原生批注覆盖范围内全部可见设计内容。按[工具能力路由](#范围路由与查看工具)打开真实交付入口。外部浏览器或受控适配器成功不能认证内置打开或原生批注。批注工具保留在宿主，不给产品加替代工具栏、评论存储或审阅覆盖层。

收尾前盘点页面／路由及重要状态，包括对话框、弹出层、校验、加载、空、禁用、可滚动内容及可视化。各内容区域说明可见审阅目标和到达方法，优先使用应用文档中可定位元素。SVG、canvas、图像或嵌入内容须在设计决定需要的粒度上暴露目标；反馈针对内部控件、标签或图中要素时只选外层容器不足。保留渲染与交互，不仅为选择方便删除内容或压平可操作视图。

检查展开菜单和各选项，而非只看折叠触发器。若真实宿主证据表明原生弹层位于不可批注文档外，选项无法选取，可在HTML原型中改用应用文档内可定位元素表示。保留标签、选项、值、可用性、位置及任务语义，提供合适角色、焦点、键盘导航、确认和关闭。不能仅因焦点转到宿主批注工具栏就折叠目标。检查展开目标在审阅中仍可达，正常交互之后仍有效。这是独立原型的展示修复，不普遍禁用原生控件，也不证明目标平台原生行为；报告保真或可访问性剩余缺口。

实际走宿主路径：进入批注模式，选可见目标，创建并提交原生评论，确认带正确页面、目标和上下文回到当前对话。覆盖盘点的每个页面和重要状态，检查各类目标／渲染机制及疑似选择故障区域。工具栏存在、点击成功、元素ID、DOM命中、截图或一条评论成功均不证明完整覆盖。按需检查滚动或覆盖目标，并确认退出批注后界面任务仍可操作。不以一次观察推定iframe普遍支持或普遍失败。

在既有证据负责文件记录入口／产物身份、实际路由／状态／目标、评论回传和缺口。API不暴露宿主批注控件时，把可操作入口交用户完成原生选择和评论，不注入替代或绕过限制。缺少宿主访问或回传证据使该操作未验证；范围内区域不可选时，批注验收未完成。报告准确缺口，保留修复反馈路径，不认证完全可批注。

### 转换与保真修复

格式或运行时转换须保留请求范围内的接受设计。转换前恢复参考修订及范围内场景、导航、控件、重要状态、信息层级和尺寸；用既有负责文件或简短任务记录，不建平行规范。明确区分请求的简化和格式转换；形成性路径不能替代已定覆盖。不为独立产物悄悄删案例、禁用可用控件或把可选择视图改成静态图。按仅界面边界保留可见交互语义，不保留底层业务实现。旧文件／服务处理器在产物中改成UI模拟，不把功能服务器或启动器作为可选工具带入。没有另行删除授权时保留历史参考文件。

预设示例结果替代业务引擎，同时保留交互合同。模拟视图须展示场景的有意义实体与选择，保留选定身份，将选择连接到输入、反馈和结果。参考中已有草稿／保存值、保存／取消、内存选择保留、依赖结果失效和控件可用性时继续保留。固定对象或参数不能替代参考中用户可选内容。重要能力无法在允许产物中表达时，展示具体缺口与影响，取得范围决定后再视为替代品。选择、确认和结果已表达时，真实后端或文件操作不算缺失UI能力。

前后比较使用相同场景、数据和状态，并匹配产品窗口、浏览器视口及适用预览比例。对范围内每条实质不同路径，在交付产物中操作保留的控件和转换，在对应检查点比较成对渲染。检查密度、层级、标签、动作及选择／结果关联，不只看外部列布局。记录批准变化中的有意差异，修复无解释损失。参考不能重新打开或缺匹配状态时，使用现有证据并指出准确比较缺口。不同案例截图或离线冒烟成功不能证明转换保真。比较和审阅完成前保留活动参考。

### 范围路由与查看工具

明确请求真实文件、持久化、计算或服务集成属于单独功能实验或实施，携既有授权和目标交回ddd-flow。不在UI产物中实现，也不把通用原型批准当成功能批准。仅记录当前原生行为可按自己的验证合同使用获准原生证据。历史批准参考仍是证据；当前设计使用的已有原型遵循[迁移要求](#已有项目迁移)。

原生行为实质影响决定且工具允许时，应用或原生验证程序可作补充证据。HTML不能回答时说明限制，在替换HTML设计交付前取得用户选择。视觉保真修复须保留HTML可操作路径，截图或启动器不能替代。

打开前从获准工具文档或已观察限制选路由。区分不支持URL协议与浏览器不可用；换协议不能恢复缺失浏览器。直接使用已知能力，不向已知仅支持HTTP的工具发送file://。路由被拒后，不重试同一不支持路径，也不能仅凭拒绝认定产物无法查看。

仅支持HTTP的可用查看工具，可在已批准预览及进程范围内，通过任务级、仅绑定loopback的静态服务器展示同一独立文件，并打开工具支持的真实HTTP地址。服务器限打包文件，无业务计算、数据或文件API；它只是查看辅助，不是必需运行依赖或另一原型。复用适合的获准服务器，保留无关服务，管理本任务进程的查看及清理，不过早结束审阅路径。缺服务器或进程授权时报告该缺口，不当成HTML缺陷。

另行验证直接离线打开，网络禁用且服务不存在；有其他明确获准方法时可使用。HTTP通过不证明离线。没有允许的浏览器或离线方法时，准确说明缺失能力和未验证操作。不绕过工具限制、改浏览器／Codex配置或用截图代替必需可操作HTML。提供真实本地HTML入口，以及临时查看URL和可用状态，保留反馈修订路径。

## 必要证据

- 网络禁用、产品／预览服务不存在时直接打开交付HTML，操作全部范围内路径，包括模拟打开／保存／导入／导出。观察文件选择事件、访问、下载、持久化及服务请求，检查处理器中点击或离线成功可能漏掉的业务I/O与计算。核对草稿和当前会话状态，不跨重载存储。不为检查停止用户无关服务。临时静态服务器通过不能证明直接打开。
- 错误、加载、空、部分、过期或高级状态只在实质影响批准流程时渲染。
- 与需求及技术设计共用代表领域场景，核对输入含义、操作、计算／数据语义、状态、反馈及结果的既有权威。说明模拟及未决语义；固定示例不验证真实领域算法。
- 在产品默认尺寸渲染默认状态，保留重要输入、动作、状态和输出关系；另查更大／更小视口，较大视口中的桌面预览保留产品窗口尺寸。
- 信息放不下时，通过有意面板、标签页、滚动或调整尺寸保持必要信息可达。
- 高级或低频控件按需显示。
- 避免多个可见区域重复同一解释。

## 批准证据

批准须对应用户可检查的渲染。局部静态问题可用渲染屏幕；流程须提供可操作入口，截图只作为允许的补充证据。源码、组件树、Markdown表格或文字可补充，不能替代必要预览。

展示时说明哪些真实可交互、哪些模拟、哪些需求与状态可见，以及用户正在批准的重要方向。交互原型须提供可用入口、实际路径及观察到的反馈／结果。构建成功、截图或未操作链接不证明路径有效；权限或能力妨碍验证时报告准确缺口，不称原型已验证。

在原位置修订项目原型。真实取舍需要比较时，在同一应用内表达备选，不维持多个入口。

## 原型生命周期

创建前解析项目根、写入范围及冲突指令。所有写入的界面原型，包括形成性探索和局部静态预览，都用下方单一目录。截图、日志和验证输出放获准任务证据位置，包括被忽略材料，不放另一原型包。无写入权限时只在内存分析。OS临时目录或项目外证据目的地须对解析目标及动作另行授权。原型创建不授予更广保存或生产访问。高优先级用户／项目指令与固定布局冲突时，说明准确冲突并取得决定，再进行依赖写入；不静默保留其他路径。

审阅和修订期间保留单一原型可用。批准修订通过可恢复Git身份或获准参考副本保留；历史证据不是另一维护入口。代表数据、模拟限制和重新打开方法随当前入口维护，在写入授权内由既有设计负责文件记录审阅身份。批准设计不能只指向已删草稿。

### 单一项目原型目录

新旧项目都只在相对项目根的docs/design/prototypes/维护一个演进原型。所有写入原型遵守此布局，没有独立单HTML例外。不在根与入口间加项目名、原型标识、功能、任务或变体目录。页面与代表路径放同一应用，局部修订保留批准的周边流程。

```text
docs/design/prototypes/
  index.html       # 可直接离线打开的界面审阅入口
  README.md        # 审阅任务、模拟限制、入口及重新打开方法
  交互设计.md       # 批准UI设计负责文件或既有权威指针
  assets/          # 可选打包图片、样式或脚本
  examples/        # 可选补充示例，不是必需fetch目标
  src/             # 可选创作源码，最终入口无运行时依赖
  tools/           # 可选维护或检查工具，不是运行时依赖
```

入口、必需文档、创作源码、必要资产、模拟数据和可重现构建说明保存在Git。不将原始数据或截图目录放入原型包。获准截图保留在项目任务证据位置。既有路径不豁免布局；按下方方法迁移本次获准原型，保留历史参考和无关文件。

选定Product Design时，在依赖创建或验证前读取[交接适配](product-design-handoff.md)。真实创作／运行根、必需QA位置、依赖及输出须在预览计划中覆盖。src/是需实际获准证据证明兼容的候选根，不是预验证插件设置。提供方必需QA报告可以作为创作QA证据留在已解析根中，任务记录保留指针；原始截图仍在任务证据位置。提供方QA、最终直接离线操作、原生批注与用户批准是不同主张。开发服务器或源码存在均不能替代唯一最终入口及其证据。

即使HTML内嵌全部展示代码与数据，也必须有index.html、README.md和交互设计.md。可选目录有内容才创建。直接打开所需示例数据内嵌或打包，不能依赖网络／文件API；examples/只存补充材料。已有文档持有UI事实时，交互设计.md只指向权威及审阅修订，不重复规范。工程或功能实验放界面产物之外，有独立启动和行为合同；服务器、构建依赖或业务处理器不因同目录而变成独立HTML的一部分。

### 已有项目迁移

已有项目首次获准创建、修改或整理原型时，核对入口、批准参考、相对依赖和入站链接，把本次原型迁移至固定布局纳入同一具体计划及授权。已批准计划覆盖时不逐文件再问。只读任务只报告路径问题，不移动文件。不扫其他项目或历史，不因原型存在推定迁移权限。更窄范围或位置冲突只暂停依赖迁移，等待用户解决。

范围内页面、案例和状态归入同一应用，不新增并行维护入口，不为适配目录丢弃批准选择。旧参考对批准含义冲突时，先解决语义再整合。保留历史参考及无关用户数据，删除须另行批准。更新入口、受影响链接和打开方法时保留可恢复审阅修订。

仅目录迁移须保留批准界面和各产物行为合同。按真实启动模式打开受影响入口，操作依赖移动的路径，验证新入口直接离线可用。交付格式也变化时应用转换保真检查。目录移动不批准设计变化，也不把功能实验变成仅界面原型。操作证据不可用时报告缺口，不认证迁移完成。

交付前核对入口、必需文档、资源和附带输出的实际路径，包括被忽略文件和工具附带文件；Git干净不证明位置合规。确认单一入口、固定布局、已修引用、可恢复批准修订及独立证据位置。在授权内修正本任务写到允许范围外的文件，保留用户数据。必需文件或保留动作不在权限内时报告缺口，不换成临时独立HTML交付。只有清理获准且审阅参考可恢复时才移除旧任务草稿，保留用户数据与活动产物。
