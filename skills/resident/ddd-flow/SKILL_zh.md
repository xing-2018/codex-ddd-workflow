# DDD Flow：设计驱动开发调度

> 仅供人工阅读的中文译本，对应同目录[SKILL.md](SKILL.md)。本文件不是Skill加载入口；执行规则以原文为准。引用文件默认保留英文原文，Git参考另提供独立中文审阅版。

用途：为项目设计、非简单实现、诊断、修复、恢复和实质性只读探索选择方法，管理授权与执行职责；独立代码审阅由ddd-review处理。

在主会话中负责路由、进度、委派、验收和恢复。先区分请求动作：普通解释无需建立DDD变更包；独立文档或图表使用对应专业方法；独立代码审阅使用`ddd-review`。项目设计、实现、诊断、修复或工作流恢复选择适用阶段或权限模式，由对应Skill负责具体方法。实质性只读项目探索可进入执行职责判断，无须编造故障或设计阶段。不要创建仅负责路由的代理、预先加载各阶段，或重复已经完成的工作。辅助能力只用于尚未解决的问题。链接到的阶段仍可读取，不改变其隐式调用策略。

## 1. 恢复权威依据

使用适用的AGENTS，以及相关需求、设计、CONTEXT和架构决策记录（ADR）。检查代码、调用者、测试、配置和数据流，将其作为证据，不能视为批准。建立并复用以下任务内边界，无需为此新建跟踪器：

- **权威基线（Authority Baseline）**：起始修订、权威资料路径和可识别的批准证据。持久化编辑前，记录已暂存、已修改或未跟踪的权威文件的哈希，以及其已批准或尚不确定的来源状态。
- **变更范围（Change Envelope）**：用户要求的行为、接口、领域算法、数据语义、并发保证、约束、验收和排除项。除非明确锁定，文件清单和执行顺序只是预测。
- **持久化写入边界（Persistent Write Boundary）**：首次写入前，确定详细计划、真实的执行授权及覆盖的目标与动作。没有明确修改授权或有界自主执行授权时，只读调查并提出方案；意图、范围或批准不明时交回用户。权威文档、记录、预览和临时产物也属于写入边界。可选辅助文档须有任务用途和写入授权。不得编造批准或认证记录。

先确定项目和工作区。DDD任务使用`.planning/PROJECT.md`、`STATE.md`对话索引及选定`changes/<change>/record.md`；普通解释和快捷查询不建包。选择用户指定变更或本对话唯一已观察绑定，不选择最新指针；对照当前已验证规范的相关记录，复用未变证据。有效恢复适配器的指针只作为声明事实，不作为权威。缺失／过期事实用[恢复方法](references/recovery.md)，结构、绑定或迁移缺口用[项目适配](references/project-adaptation.md)。首次获准写入覆盖范围内必要初始化及无损迁移；只读任务只报告缺口。需求、设计与批准仍由原持有方负责，链接而不复制。只有具体生命周期问题才读取[项目Skill](references/project-skills.md)；初始化不安装Skill或改变配置。

## 设计审批

实现初始设计或语义变化前取得批准。跨阶段、跨轮次复用可识别的批准；仅缺少设计文件不使批准失效。代码、测试和实验不能重新定义已批准的行为或验收条件。

实质性决策会改变结果、接口、领域或数据语义、安全、依赖承诺、成本或难以撤销的约束。独立查明事实；提交用户决定的是尚未解决的重要选择，不是效果等价的私有实现细节。

准备设计或设计差异、处理权威或持久化方面的不确定性，或在已授权实现之外准备临时证据时，阅读[设计审批](references/design-approval.md)。仅设计任务中的UI预览也须先阅读该文件。只暂停依赖未决事项的动作。

记录写入不被允许时，使用可恢复的会话批准。G1需求、G2设计、G3实施和G4用户验收标识批准对象，不要求固定会议。同一回复可覆盖多个具名对象；设计批准本身不授予写入权限，技术检查不等于用户验收。只为受影响对象读取[项目关口](references/design-approval.md#project-gates)。

## 2. 选择一个阶段

- **直接处理（Direct）**：普通问题或明确获准的机械编辑，且没有尚未解决的行为、接口、引用或迁移影响；退出DDD流程，不跳过写入边界和详细计划要求。已知文件或符号定位直接由主会话完成。实质性只读项目探索先界定有界证据问题，再进入执行职责判断，不编造故障或设计阶段。
- **设计（包括UI）**：需求、重要技术决策、交互、层级或可见行为尚未解决；阅读[ddd-design](../ddd-design/SKILL.md)中适用的分支，用户要求时使用仅需求模式。需求、算法、数据和UI使用同一场景，将矛盾交回相应事实的负责方。
- **实现（Implementation）**：已批准依据与实现授权覆盖一轮连贯工作或一个已就绪切片；阅读[ddd-implement](../ddd-implement/SKILL.md)。
- **只读诊断（Diagnosis）**：只调查故障时，使用[ddd-implement诊断模式](../ddd-implement/SKILL.md#select-authorization-mode)，不修改项目文件。
- **获准修复（Repair）**：用户要求在既有批准契约内修复时，使用[ddd-implement修复模式](../ddd-implement/SKILL.md#select-authorization-mode)；重要契约变化先回设计。

已经确定要做的非简单实现不属于Direct。保留变更范围之外的已批准事实；当前用户提出的变化应经过审批，不能静默恢复为旧行为。

选择阶段与权限后，在实质执行有界角色候选任务前完成下方职责判断。初步扫描可确定范围，但不能先完成候选任务才决定执行者。

## 选择执行职责

选择阶段与权限后，确认任务中是否有以下有界worker任务。整个阶段、未决设计决定、用户互动、整合与最终验收不属于worker任务。

| 当前工作 | 有界候选任务 | 角色与方法 |
| --- | --- | --- |
| 设计或其他阶段受外部工程事实阻塞 | 一个影响当前决定、但不将决定交给worker的外部事实 | `research-worker`使用[ddd-design研究方法](../ddd-design/references/research.md) |
| 项目探索、诊断或修复 | 一个只读调用链、数据流、边界或因果证据问题 | `diagnosis-worker`使用[ddd-implement证据worker入口](../ddd-implement/SKILL.md#delegated-evidence-worker-entry)；探索无需故障报告 |
| 实施或获准修复 | 一个接口已定、可独占写入的已批准就绪切片 | `implementation-worker`使用[ddd-implement实施worker入口](../ddd-implement/SKILL.md#delegated-implementation-worker-entry) |
| 实施后或独立代码审阅 | 一个冻结差异或明确代码路径快照的Design与Standards审阅 | `review-worker`使用[ddd-review](../ddd-review/SKILL.md) |

默认主会话执行。短而确定的检查、小型审阅、已知文件或符号查找不加载协议。对超出快捷路径的有界候选任务，在实质执行前判断其独立结果是否值得准备、派发、收集和核验成本。角色可用、可分离切片、大量阅读或新上下文本身均不足；不建立固定worker流水线。

仅当冻结对象或竞争证据需要具体独立判断、有界上下文隔离能返回可定位证据，或存在实际并行进展，且权限与宿主条件满足时委派。说明所需证据或判断及本地执行为何不适合；并行工作还须说明主会话同时完成什么和worker返回什么，等待及后续审阅不算并行。worker意见须有可核对的权威与输入。明确委派请求仍遵守角色、权限和独立性边界。

范围、依赖、用户要求及宿主条件未变时复用判断，阶段变化不重置。不为制造收益扩大任务，不编造token价格或数值门槛。理由成立后，用重复`--heading`参数一次读取[执行协议](references/execution.md)缺失的**Record and dispatch**、**Worker contract**及**Accept a result**章节。本地执行不读取派发细则，不新增判断台账。

## 按条件读取参考

复用已加载或已查明的适用指导。用户明确要求加载最新Skill，或已知适用指导更新时，在依赖工作前一次补读当前任务相关的新内容，包括引用的规则；只重读入口不代表引用已刷新。其他情况只补读缺失、变化或冲突的部分。刷新后继续复用，不每轮扫描版本或哈希。阶段切换或上下文压缩本身不要求重读整个Skill或项目文档；绑定丢失时从当前活动记录及相关来源恢复，不重新通读文档。先判断适用性，再加载分支细节。

| 条件 | 参考 |
| --- | --- |
| 首次项目写入或Git变更 | [Git英文执行规则](references/git.md)，[中文审阅版](references/git_zh.md)仅供人工审阅 |
| 引用对话中有缺失背景或权威 | 请求历史前提取[execution.md的Conversation evidence](references/execution.md#conversation-evidence)，只恢复必要决定与证据 |
| 产品变化、修复、构建或交付检查中尚未解决的版本与交付要求 | [版本与交付](references/versioning-and-delivery.md)；复用已查明的项目配置和判断；明确可丢弃且没有产品或交付物变化的夹具无需交付过程 |
| 测试选择、创建、维护或审阅 | [测试与测试维护](../ddd-implement/references/testing.md)；不触发TDD |
| 大型工具结果、长时间运行的操作或重复命令失败 | 使用[read_section.py](scripts/read_section.py)及`--heading "Efficient tool execution"`，仅提取[execution.md](references/execution.md)中的高效工具执行节 |
| 有依据的委派、受管结果验收、受管依赖或阻塞变化、受管工作恢复 | 完成上述职责判断后，只读取[执行与恢复](references/execution.md)缺失章节：派发用**Record and dispatch**、**Worker contract**、**Accept a result**；验收用**Accept a result**；恢复用**Resume from durable evidence**及必要的**State transitions** |
| 明确要求规划，或规模、多会话、实际阻塞关系需要任务图 | [规划](references/planning.md) |
| 项目会话恢复、活动记录缺失或过期、昂贵事实恢复、明确要求便携交接 | [恢复](references/recovery.md)；只读取相关事实和现存活动变更 |
| 写入记录phase／status，包括仅原型工作 | 使用[状态词汇及记录检查](references/recovery.md#state-vocabulary)，复用对应实际输入的可辨认检查 |
| 可选hook方法、覆盖或启用问题未决 | [生命周期适配器](references/lifecycle-hooks.md)；不可用时保留人工路径，启用另行授权 |
| 工作流结构缺失或过期、项目绑定变化或迁移未决 | [项目适配](references/project-adaptation.md)；只比较相关差异并复用未变绑定 |
| 匹配、核查或变更项目级受管Skill | [项目Skill](references/project-skills.md)及固定来源工具；配置变化另行审批 |

从当前清单或已验证位置解析`<ddd-flow>`，使用`scripts/read_section.py <source> --heading <exact-title>`；重复`--heading`读取已知章节。独立阶段／审阅入口可只提取**Choose execution ownership**。工具先验证全部标题，再返回去重源行及路径／SHA-256；在Worker contract复用身份，业务验证仍由worker负责。标题失败直接返回准确可用标题，不返回正文；从该输出选择，不猜测。标题仍缺失时才用`--list-headings`。保留失败状态，不算已加载指导。工具不可用时报告缺口，或使用相同章节边界的有界读取，不读全文。

本地执行与委派执行的受管结果共用执行协议。活动`.planning`记录链接既有设计、任务、报告和Git证据，不复制它们。小任务无需任务图或单独计划。昂贵事实和明确要求的便携交接使用[恢复方法](references/recovery.md#recover-facts-without-a-second-memory-store)；不另建状态或默认记忆存储。

## 参考修订审阅

以下同步审阅英文引用的相关规则，不作为额外执行链；完整原有引用仍由英文文件持有。

### 指导复用与对话证据

[高效工具执行](references/execution.md#efficient-tool-execution)：在上下文内的AGENTS、角色和方法视为已加载。发出读取前指出缺失的来源或章节；新轮次、阶段变化或恢复指针不使已有指导失效。只补读缺失、改变、冲突部分或明确要求的刷新。复用先前有效身份与准确标题，用既有脚本批量读取必要章节；结果截断时只补缺失片段。没有变化证据时，不反复哈希或扫描未变输入。

[对话证据](references/execution.md#conversation-evidence)：先确定缺失的需求、批准、纠正、已接受结果或阻塞，在工具允许范围内读取相关轮次，初始不附带工具输出。保留来源对话、轮次身份、顺序和分页游标；只为恢复缺失事实及其权威补读较早轮次。

结构化结果先在工具编排中筛选再返回模型，保留相关用户指令与主会话结论、条件及来源；省略思考条目、命令正文、补丁和无关输出。结果大小选项或includeOutputs:false仍可能包含大量命令项，须明确选字段并限制返回文本。必要内容过大时分割相关轮次或读取具体条目，不静默截断决定。检查所有并行结果、保留各项错误，报告证据缺口；仅为解决当前问题展开特定命令、差异或收据。其他对话只提供证据，不授予联系或接管权限；获准保存时链接既有记录，不复制对话或新建台账。

### 任务包首次写入

[项目适配](references/project-adaptation.md#unified-workflow-and-migration)：先按实际阶段准备必需的brief／design事实负责方指针、合法记录字段及已有批准依据，尽可能用一次受支持补丁写入完整包及绑定。分开写入时先建必要文件，最后发布STATE绑定并保留其他条目。既有负责文件仍持有权威，指针不创造新设计、审批会议或重复规范。

初始化中的hook警告只表示结构反馈，不判产品失败或授权修复。只完成获准的缺失文件／指针，再检查完整包一次；先用问题路径和已说明的校验接口处理，仅在校验器行为确有疑点时读取其源码。被排除的写入仍排除，未完成的包不能声称结构有效。

## 3. 继续或停止

结束前，对照请求结果与已验收成果，在当前轮执行每项可行的授权动作。进度承诺、首版实现、阶段结束或worker返回不代表完成；阶段名称不缩小已授权实现或交付结果。仅设计、仅规划和明确停止请求保留其边界。复用已定批准；真实歧义、阻塞或权限关口只暂停依赖动作，先完成独立授权工作，再报告缺少的具体条件和受阻动作。遵循全局下一步报告规则，不在完成后制造审批问题或可选跟进。

## 4. 完成

`ddd-implement`针对冻结差异调用`ddd-review`，仅完成未决行为问题、具体回归风险或项目要求支持的检查。复用有效结果；阶段切换和提交不触发另一轮验证。原结果和必需保护确立后，停止探针、套件及额外重启，继续剩余授权交付。受管结果按执行协议验收；worker返回结果不等于验收。遵循版本与Git完成规则，不擅自构建或发布。

遵循全局报告规则，说明经历的阶段、有意义的跳过项、权威与批准证据，以及仓库操作。只有所需结果、适用批准和必需检查均已满足，才算完成。
