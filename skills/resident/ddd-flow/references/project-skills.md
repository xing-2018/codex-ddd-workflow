# Project Skills

Read for a concrete project Skill question. Determine candidate sources from the target project's authority and the user's request; this Skill's source repository is not automatically a candidate or an installation target. Project-owned methods remain in their own project. Workflow initialization or migration never grants Skill installation, Codex configuration changes or access to another project.

Treat a catalog supplied by a selected source as a shortlist, not an installation manifest. Match the current task, approved target stack and exact version, trusted fixed source, required tools, permission and existing global or project names. Inspect declarations, lock and actual environment separately. A different or unknown dependency version needs matching project or primary guidance, not a project dependency change. Native Three.js guidance is not interchangeable with React Three Fiber. A tool prerequisite that is unavailable or unauthorized makes the candidate unusable for that route.

Project Skills belong at the named project's root `.agents/skills/<name>` unless a verified monorepo working directory requires a narrower path. Codex discovery depends on the starting directory and its ancestor path; it does not merge same-named Skills. Treat a different global or project Skill of the same name as a conflict. Do not presume project priority, rename or remove the other copy without a migration decision.

When a project selects one or more managed Skills, maintain `.planning/skills.lock.json` only for actually approved entries. Each entry records source repository, full Git commit, source subpath, Skill version, complete tree SHA-256, target subpath, compatibility evidence and approval reference. A version string without tree identity is insufficient. The lock is a workflow record, not a native Codex enforcement mechanism. Do not copy project-specific methods across projects without authorization.

For a selected fixed source laid out as `skills/non-resident/<name>`, [project_skills.py](../scripts/project_skills.py) can perform bounded `audit`, `plan` and, after an exact user decision, `apply`; its FastAPI compatibility check covers only the bundled `0.136.3` snapshot. Use a source-appropriate method for other layouts or versions. `audit` and `plan` are read-only. Before `plan`, resolve a concrete backup location permitted by the target project's rules; pass it with `--backup-root` so it is included in the reviewed plan. `apply` must receive that plan and use the same location; its arguments are not approval. First compare the fixed Git source, entire target, lock, same-name directories, path links and backup location. The script refuses source or target drift; do not patch the installation copy, merge directories or install from the mutable worktree. A missing copy of an already approved, identical lock entry may be restored only when the original installation authorization covers that restoration. Adding, upgrading, replacing, removing, changing metadata or resolving a conflict needs an exact plan approval. Preserve backups outside Skill discovery in a location allowed by the project; the location may be inside or outside the repository. Compare bytes after copying; a matching tree proves file delivery, not native discovery or actual task behavior.

An unknown same-name target or drift is a `CONFLICT`, even when `--approved-change` is supplied. Resolve its provenance and replacement as a separate reviewed operation under the repository's installation procedure; this script does not silently turn an existing unknown directory into a managed copy.

Run the scripts with a verified Python 3.11+ management runtime and Git executable; do not install either into the product environment merely for Skill management. Keep the JSON plan as the exact approval object. If `apply` reports `RESTORE_FAILED` or nonempty `cleanup_pending`, preserve its backup and local holding paths for explicit recovery; do not continue another synchronization or assume the project is clean.

If compatibility cannot be established, use existing project methods or version-matched primary documentation. Report the gap; do not install a vaguely related Skill or change the product stack to fit the catalog.

FastAPI recognition accepts exact declarations with extras, and simple numeric comparison ranges only when an exact applicable declaration or lock resolves them. It does not use the management machine as the product environment. For conditional declarations, supply the explicitly verified target fields in the selected entry's `compatibility.marker_environment` (for example `python_version` or `sys_platform`); missing fields, direct URLs, wildcard/compatible-release specifiers or unsupported marker syntax report `UNAVAILABLE`, not a fabricated version conflict. Markers support quoted strings, explicit standard environment names, parentheses, `and`/`or`, equality/order and membership; version comparisons for Python/implementation versions require numeric release components. Inactive declarations do not activate a lock-only copy. Declaration/lock disagreement is a `CONFLICT`; the selected snapshot must still be exactly `0.136.3`. These parser limits do not authorize changing dependencies or configuration.
