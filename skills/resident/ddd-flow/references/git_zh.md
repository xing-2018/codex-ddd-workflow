# Git规则：中文审阅版

> 对应[英文执行版](git.md)，仅供人工审阅，不作为额外执行指令加载。

项目写入或Git操作前读取，包括机械编辑；读取本参考本身不启用DDD。

使用工作树须有本次会话仍有效的明确授权。提交或推送请求不授权创建、切换本地分支或创建远端分支。

首次写入用户指定的非Git根目录前，除非用户禁止，否则初始化Git。不得创建嵌套仓库；基线提交前排除敏感文件、生成产物和大文件。

必需审阅和检查通过后，只在本地提交本任务内容，不留下本任务未提交的改动。完整保留其他任务的内容和暂存状态；工作树有其他改动时无须清空。发现无法隔离的改动时报告，不能纳入或丢弃无关内容。只读任务不创建提交。已知存在并发Git活动时，按[共享检出协调](execution.md#shared-checkout-coordination)协调完整的暂存、审阅和提交过程；保留其他任务的暂存及锁，无法隔离的依赖须报告，不混合候选。使用Conventional Commit类型和简体中文提交信息。

## 提交信息

按实际变化选择类型：新增能力用`feat`，修正问题用`fix`，仅文档变化用`docs`；其他变化使用适合的Conventional Commit类型。发布动作或版本递增不决定类型。版本影响仍按项目版本规则独立判断。

标题说明具体变化及结果，读者无需打开差异就能知道新增或修正了什么。版本号可作为补充；“发布版本”“优化内容”等笼统标题不足以描述变化。原因、使用影响或重要限制需要解释时补充正文，简单改动不强制长正文。

提交前，将类型、标题及正文与完整暂存差异和批准范围对照。确认描述符合实际变化和证据，排除个人信息、私有来源、本机路径和凭据。自动生成的提交信息也须同样审阅，不能替换成固定的发布标题。这些检查不授予提交、推送或改写历史的权限。
